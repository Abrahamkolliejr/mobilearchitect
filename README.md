# CS 360 Mobile Architect & Programming Portfolio

## Project Three: Inventory Manager App

**Abraham Kollie Jr.**

### 1. Briefly summarize the requirements and goals of the app you developed. What user needs was this app designed to address?

For this project, I developed an Inventory Manager app to help users keep track of products in a warehouse. The main goal was to make inventory management easier and more organized. Users can create an account, log in, add inventory items, update quantities, and delete items. The app also sends SMS notifications when an item reaches zero. This helps users know when products need to be restocked.

### 2. What screens and features were necessary to support user needs and produce a user-centered UI for the app? How did your UI designs keep users in mind? Why were your designs successful?

My app includes a login screen, an account creation feature, an inventory dashboard, and an SMS notification settings screen. I wanted the design to be simple so users could understand it without needing instructions. I used clear buttons, easy-to-read text, and a simple layout. The inventory dashboard allows users to see their products and quantities in one place. I believe my design was successful because it was easy to navigate and helped users complete tasks quickly.

### 3. How did you approach the process of coding your app? What techniques or strategies did you use? How could those techniques or strategies be applied in the future?

I approached coding my app by working on one feature at a time. I started with the user interface and then worked on the login system, database, inventory features, and SMS notifications. I tested each feature before moving to the next one. When something did not work, I reviewed my code and made changes until I fixed the problem. In the future, I can use this same approach to stay organized when working on bigger projects.

### 4. How did you test to ensure your code was functional? Why is this process important, and what did it reveal?

I used the Android Studio emulator to test my app. I created an account, logged in, added inventory items, changed quantities, and tested the delete feature. I also tested the SMS notifications by setting an item's quantity to zero. Another important test was denying SMS permission to make sure the rest of the app continued working. Testing helped me find problems and make sure the app worked correctly before finishing the project.

### 5. Consider the full app design and development process from initial planning to finalization. Where did you have to innovate to overcome a challenge?

One of my biggest challenges was getting the SMS notification feature to work correctly. At first, the app saved inventory items, but the text messages were not showing up. I had to review the code, check the permissions, and test different phone number settings in the emulator. After making changes, I was able to get the notifications working. This experience taught me to keep trying different solutions instead of giving up when something does not work.

### 6. In what specific component of your mobile app were you particularly successful in demonstrating your knowledge, skills, and experience?

I believe I was most successful with the inventory dashboard and database features. I was able to create an app that allows users to add, edit, and delete inventory items while keeping the information saved. I also learned how to connect these features to the user interface. Seeing my app work in the emulator made me proud because it showed how much I learned throughout the course.

## Final Reflection

Overall, this project helped me better understand mobile app development. I learned how to design an app, write Java code, work with a database, and test different features. I know there is still a lot for me to learn, but this project gave me more confidence in my programming skills. I plan to use what I learned in future computer science courses and eventually in my career.
